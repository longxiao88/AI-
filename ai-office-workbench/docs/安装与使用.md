# 安装与使用

## 1. 准备环境

- Node.js 22.5 或更高版本（推荐 24 LTS），从 https://nodejs.org 下载安装。装好后打开终端（Windows 用 PowerShell 或命令提示符，macOS 用「终端」）执行 `node -v`，显示 `v22.5.x` 或更高即可。用 Node 22.x 时启动脚本会自动带上 `--experimental-sqlite`（SQLite 在 22.x 是实验特性，会有提示但不影响使用）；用 Node 24 LTS 则无需任何额外操作。
- 浏览器：Chrome、Edge 或 Safari 的新版本。主题切换的揭幕过渡需要 Chrome / Edge 111+ 或 Safari 18+；使用更旧的浏览器或 Firefox 时会在切换主题时直接瞬时切换，其余功能不受影响。
- 只有运行端到端测试（`npm run test:e2e`）时才需要安装 Google Chrome，日常使用不需要。
- 不需要安装数据库，数据用 Node.js 自带的 SQLite 保存在本机。
- 想用「找回密码 / 绑定邮箱」才需要准备一个可用的邮箱 SMTP 服务（见第 4 节），不配也不影响其它功能。

## 2. 首次安装与启动

把压缩包解压到一个路径里没有特殊符号的目录，终端进入解压后的 `ai-office-workbench` 目录，依次执行：

```sh
npm ci
npm run build
npm start
```

- `npm ci` 按锁文件安装依赖，需要联网，只在第一次或更新版本后执行。较新的 npm 可能提示 install-scripts 相关警告，不影响使用。
- `npm run build` 生成前端页面到 `dist/`，修改前端代码后需要重新执行。
- 看到 `AI 办公助手已启动：http://127.0.0.1:4318` 后，用浏览器打开这个地址。
- 停止服务：在运行 `npm start` 的终端按 Ctrl+C（Windows 如出现「终止批处理操作吗」输入 Y 回车）。

第一次打开会进入「创建账号」：账号为 3–40 位字母、数字或 `._-`，密码至少 8 位。

服务只监听 127.0.0.1，同一局域网的其他电脑和手机无法访问。

### 2.1 多账号

一个工作空间可以注册多个账号，注册后随时在登录页切换：

- 在登录页点「注册新账号」，填账号名、名字、密码即可再建一个。
- 已注册的账号会列在登录表单下方，点一下就把账号名填进输入框，不用手打。
- 点左侧导航列最下方的「退出登录」（头像与账号名那条的下方）会回到登录页，此时选择另一个账号登录即可切换。
- **各账号的数据完全隔离**：写作、会议、项目、文档、知识库、任务看板、操作日志都只属于自己的账号，互相看不到。API 地址与模型名称也是各账号独立配置的。

> AI 的 API Key 是全局共享的（只存在服务进程内存里），与账号无关；重启服务后需要重新填写。

## 3. 配置 AI 模型

进入「设置」页填写三项，点「保存并测试连接」，看到「连接成功」即可使用 AI 功能：

| 项目 | 说明 |
| --- | --- |
| API 地址 | 服务商提供的 OpenAI 兼容接口基础地址，通常以 `/v1` 结尾，不要带 `/chat/completions`。必须是 https；本机模型服务可用 http，例如 Ollama 为 `http://127.0.0.1:11434/v1` |
| 模型名称 | 服务商文档中的模型 ID，大小写要一致 |
| API Key | 服务商后台申请的密钥。本机 Ollama 不校验密钥，随便填一串字符即可 |

- API Key 只保存在服务进程的内存里，不写数据库、日志或浏览器。**每次重启服务后需要重新填写 Key**，API 地址和模型名称会保留。
- API 地址与模型名称按账号保存，切换账号后看到的是该账号自己的配置。
- 测试连接会发送一条很短的请求，可能产生少量费用。
- 截图或录屏时注意不要拍到 Key。
- 没有配置 AI 时，所有记录的新增、修改、删除、搜索都照常可用。

## 4. 邮件服务（SMTP）

「找回密码」和「绑定邮箱」需要发验证码邮件，所以要配置一个发件邮箱。**不用这两个功能可以不配。**

两种配置方式，任选其一：

### 方式一：在网页里配置（简单）

进入「设置 → 邮件服务（SMTP）」填写：

| 项目 | 说明 |
| --- | --- |
| SMTP 服务器 | 如 `smtp.qq.com`、`smtp.163.com`、`smtp.exmail.qq.com` |
| 端口 | 465（SSL）或 587（STARTTLS） |
| 连接方式 | 与端口对应，选 SSL 或 STARTTLS |
| 发件账号 | 你的完整邮箱地址 |
| 发件人名称 | 可选，邮件里显示的发件人名字 |
| 授权码 / 密码 | **邮箱服务商提供的 SMTP 授权码，不是邮箱登录密码** |

授权码需要用邮箱服务商提供的「授权码」而不是登录密码（一般在邮箱设置里开启 SMTP 服务时生成）。留空表示沿用上次保存的值，不必每次重填。

保存后授权码会用 **AES-256-GCM 加密**再写入本机数据库，密钥单独存放在 `data/.mail-key` 文件中，只有两者都在才能还原。数据库文件单独被复制走是拿不到授权码的。

### 方式二：用环境变量（更彻底）

如果不想让授权码落进磁盘，改用环境变量——这种方式下**授权码完全不写入数据库**：

```sh
# macOS / Linux
SMTP_HOST=smtp.qq.com SMTP_USER=you@qq.com SMTP_PASS=你的授权码 npm start

# Windows PowerShell（逐行执行）
$env:SMTP_HOST="smtp.qq.com"
$env:SMTP_PORT="465"
$env:SMTP_USER="you@qq.com"
$env:SMTP_PASS="你的授权码"
npm start
```

| 变量 | 说明 |
| --- | --- |
| `SMTP_HOST` | 服务器地址，**必填** |
| `SMTP_USER` | 发件账号，**必填** |
| `SMTP_PASS` | 授权码 |
| `SMTP_PORT` | 端口，默认 465 |
| `SMTP_SECURE` | 是否用 SSL；不填时按「465 走 SSL，其余走 STARTTLS」推断 |
| `SMTP_FROM_NAME` | 发件人名称，可选 |

**同时提供 `SMTP_HOST` 与 `SMTP_USER` 即视为启用**，此时环境变量优先级高于数据库，设置页对应表单变成只读并给出提示。`.env.example` 里有同样的说明（项目不会自动读取 `.env` 文件，只是说明模板）。

## 5. 各模块怎么用

| 模块 | 手动功能 | AI 功能 |
| --- | --- | --- |
| 工作台 | 概览、最近记录、快捷入口 | — |
| 全局搜索 | 跨五个模块检索全部记录，命中处显示片段 | — |
| AI 写作 | 标题、要求、结果可编辑保存；可一键存入知识库 | 撰写 / 润色 / 摘要；结果可编辑、复制、导出 TXT |
| 会议纪要 | 日期、原文、结论、待办；待办可转为项目任务 | 由原文生成「重点与结论 + 待办」草稿，编辑后应用，再点保存 |
| 项目管理 | 项目说明、任务增删改、三种状态 | 先保存项目，再生成任务草稿；勾选、改名后批量加入 |
| 文档分析 | 导入 UTF-8 的 TXT / Markdown（≤200 KB），写分析笔记 | 生成概述 / 要点 / 建议行动草稿；生成**工程导图**并可导出 |
| 知识库 | 资料、标签、关键词检索；从资源库取正文导入 | 用命中的资料整理答案并标注来源；没有命中不调用 AI |
| AI 问答 | — | 多轮追问，最多 20 轮；可复制、导出 TXT、存入知识库 |
| 操作日志 | 查看每次增改删的前后内容，可回溯撤销 | — |
| 时钟与计时 | 倒计时、秒表 | — |
| 个人资料 | 昵称、角色、简介；绑定邮箱（需验证码） | — |
| 界面外观 | 日夜主题切换（自底部向上揭幕）、背景气泡、场景轮播、动效开关 | — |
| 设置 | AI 连接、邮件服务配置、清除密钥 | — |

使用规则：

- AI 结果都是草稿，应用后还要点「保存」才写入；保存前可以随意修改。请人工核对日期、金额、电话等细节。
- 同一时间只处理一个 AI 请求，等待超过 60 秒会提示超时；失败时输入和已有内容都会保留，不会自动重试。
- AI 原文每次最多 20,000 字，超出会提示缩短，不会自动截断。
- AI 问答的内容只在当前页面，不保存到数据库；离开或刷新前请复制或导出。它不会读取知识库，需要基于资料回答请用知识库页面。
- 有未保存的修改时，切换页面会先确认。

### 5.1 全局搜索

侧边栏「全局搜索」一个入口就能查到所有模块的内容：

- 输入关键词即实时过滤，覆盖标题、正文、会议原文与结论、项目说明、文档原文与笔记、写作的输入与输出。
- 每条结果标出所属模块，并显示命中位置前后的片段。
- 点任意一条结果直接跳到对应模块并打开该条记录。
- 只搜索当前登录账号自己的内容。

### 5.2 工程导图

在「文档分析」里选中一条已保存的文档，点「生成工程导图」：

- AI 会把文档原文提炼成树状结构（中心主题 → 各分支 → 子项），先在页面上以导图形式展示，**属于草稿，不写数据库**。
- 可导出三种格式：
  - **PNG**：适合直接放进报告；按 2 倍尺寸生成，不模糊。
  - **SVG**：矢量图，可无限放大。
  - **Markdown 大纲**：缩进列表形式，可直接导入幕布、Obsidian、XMind 等工具继续编辑。
- 导出效果与页面显示完全一致。

### 5.3 从资源库导入资料

上传文件只发生在**资源库**一处；知识库与文档分析不再各自接收本地文件，而是「从资源库取正文」。

知识库页点「从资源库选择文件」后：

- 弹出资源库文件列表，点一个文件即读取它的正文。
- 只显示能提取正文的格式（`.docx`、`.xlsx`、`.txt`、`.md`、`.csv` 等）；PDF 与图片标注为「仅可下载」，需要到资源库预览或下载。
- 资源标题填进标题，正文填进「知识正文」；关键词保持你已填写的内容，不做猜测。
- **只填充表单、不会自动入库**，也不复制、不改动资源本身，确认内容后自己点「保存」。

文档分析页的「从资源库取原文」同理：正文填进「原文」，标题为空时沿用资源标题。

### 5.3.1 上传压缩包

资源库支持直接上传 `.zip`：

- 压缩包**自动解压**，里面每个文件各存为一条资源，共用上传时选的分类。
- **压缩包本身也会保留一条资源**，列表里点它就能下载回原始 zip。
- 目录、隐藏文件、macOS 的 `__MACOSX` 资源分支、不支持的格式会被自动跳过，提示里会写明跳过几个。
- 上限：单次最多 50 个文件、解压后合计 200 MB；超出时只处理前一部分，提示会标注「已达上限」。
- 压缩包条目不支持在线预览（显示「不支持预览」），下载即可；解压出来的文件按各自格式正常预览。

批量导入一批制度、模板、合同这类文档时，打包上传比逐个选快得多。

### 5.4 会议待办转项目任务

在会议纪要里点「转为项目任务」：

- 待办会按行拆分，自动去掉 `-`、`*`、`1.` 这类列表符号并去重。
- 弹出面板里勾选要加入的条目，再选一个目标项目，确认后写入该项目看板（状态为「待开始」）。
- 只写入勾选的条目，不会重复入库。

### 5.5 界面外观

- **主题切换**：点右上角的「白天 / 黑夜」按钮，新主题会从屏幕底边向上揭开占满全屏，边界是一条柔和的过渡带。Firefox 等不支持视图过渡的浏览器会直接瞬时切换，功能不受影响。
- **动效开关**：关闭后，主题切换改为瞬时完成，背景气泡、场景轮播、卡片流光也一并停止。系统开启了「减少动态效果」时效果相同。
- **背景气泡**：工作台首页与登录页的背景有缓慢上升的气泡，点击会破开，颜色跟随主题。
- **场景轮播**：首页顶部与登录页的四张场景图每 5 秒自动切换（擦除过程 1.5 秒），切换时当前图会从一侧被「擦掉」，露出下面的图。可以**按住鼠标左右拖动**——往左拖看下一张（当前图从右往左退去），往右拖看上一张，松手超过 18% 就切过去，不到则回弹；也可以点底部胶囊直接跳转。鼠标停在上面、键盘聚焦或切到其他标签页时自动暂停，移开后继续。
- 这些动效只为观感，关闭后所有功能照常可用。笔记本电脑电量紧张时可以关掉。

演示用的案例输入见 `docs/演示案例.md`。

## 6. 数据、备份与恢复

- 数据库文件：`data/workbench.sqlite`，第一次启动时自动创建。
- 加密密钥文件：`data/.mail-key`，第一次保存 SMTP 授权码时自动生成。
- 备份：先按 Ctrl+C 停止服务，再把**整个 `data` 文件夹**复制到别处（可在文件夹名里加日期）。不要在服务运行时复制。
- 恢复：停止服务，删除或改名当前 `data` 文件夹，把备份的 `data` 文件夹复制回原位置，再 `npm start`。
- 数据库里保存了账号资料、业务记录、模型地址与名称，以及**加密后**的 SMTP 授权码；不含 AI 的 API Key。备份时请连同 `.mail-key` 一起，否则恢复后需要重新填写授权码。

## 7. 升级到新版本（保留数据）

1. 停止旧版服务，按上一节备份 `data` 文件夹，旧目录先不要删。
2. 把新版压缩包解压到一个新目录。
3. 把旧目录的 `data` 文件夹复制到新目录里（与 `package.json` 同级）。
4. 在新目录执行 `npm ci`、`npm run build`、`npm start`，用原账号登录，在设置页重新填写 API Key。
5. 首次启动会自动迁移数据库结构（从 0.2.0 升级到 0.3.0 会新增 `accountId` 等字段），终端没有报错即可。
6. 确认数据都在以后再删除旧目录；有问题可以回到旧目录继续使用。

## 8. 更换端口或数据库位置

默认端口 4318。被占用时启动会提示「端口 4318 已被占用」，可以先关掉已在运行的那个窗口，或换一个端口：

```sh
# macOS / Linux
PORT=4319 npm start
# Windows PowerShell
$env:PORT=4319; npm start
# Windows 命令提示符（两行分别执行）
set PORT=4319
npm start
```

数据库位置可用 `DB_PATH` 指定（写绝对路径），用法同上。密钥文件会跟随数据库放在同一目录。项目不会自动读取 `.env` 文件，`.env.example` 只是说明。

## 9. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| `node` 或 `npm` 不是内部或外部命令 | 没装 Node.js，或装完没重新打开终端 |
| 提示「需要 Node.js 22.5 或更高版本」 | 升级 Node.js 到 22.5+（推荐 24 LTS），重新打开终端后再执行一次 `npm ci` |
| `npm ci` 很慢或失败 | 检查网络；公司/校园网可换网络或配置 npm 镜像后重试 |
| 提示「端口 4318 已被占用」 | 已有一个服务在运行（可能是旧版本），关掉它或换端口（见第 8 节） |
| 提示「未找到前端页面 dist/」，浏览器显示 Cannot GET / | 先执行 `npm run build` 再 `npm start` |
| 浏览器打不开页面 | 确认终端里服务还在运行，地址是 http://127.0.0.1:4318 |
| 「请先在设置中填写 API Key」 | 重启服务后 Key 会清空，在设置页重新填写 |
| 「API Key 无效或已过期」 | Key 填错、过期或复制时多了空格 |
| 「模型或 API 地址不可用」 | API 地址或模型名称写错；地址不要带 `/chat/completions` |
| 「调用额度不足或请求过于频繁」 | 服务商账户余额或频率限制，去服务商后台查看 |
| 「AI 响应超时」 | 模型较慢或网络不好，缩短输入后手动重试 |
| 「AI 返回的内容不符合约定格式」 | 会议 / 项目 / 文档 / 工程导图要求模型返回 JSON，个别模型偶尔不按格式回答，重试一次或换一个模型 |
| 「API 地址需使用 HTTPS」 | 只有本机地址（127.0.0.1 / localhost）允许 http |
| 导入文档提示不是有效的 UTF-8 | 用记事本「另存为」选择 UTF-8 编码后再导入 |
| 连续输错密码被锁定 | 连续失败 10 次锁定 15 分钟，等待后再试 |
| 「该账号名已被使用」 | 账号名在同一个工作空间里唯一，换一个名字 |
| 忘记密码，但找不到「忘记密码？」入口 | 该入口只在已有账号、且处于「登录」Tab 时显示；先确认已有账号注册过 |
| 「发件邮箱尚未配置」 | 还没配置 SMTP。按第 4 节配置后即可使用找回密码与邮箱绑定 |
| 「验证码不正确」或「验证码已过期」 | 验证码 5 分钟失效、最多试 5 次，重新点一次「发送验证码」 |
| 申请验证码后提示已发送，但邮箱没收到 | 这是防账号枚举的设计：账号不存在或未绑定邮箱时也会返回同样的提示。请核对账号名、确认邮箱已绑定，并检查垃圾邮件文件夹 |
| 「该邮箱已被其他账号绑定」 | 一个邮箱只能绑定一个账号，换一个邮箱 |
| 升级后设置页的 SMTP 授权码不见了 | 授权码不会回显（接口从不返回），只要显示「已加密保存授权码」就是还在；不确定可重新填一次 |
| 复制 `data` 到新机器后发不出邮件 | 密钥文件 `.mail-key` 没一起复制，或换了目录。重新填写一次授权码即可 |
| 切换主题时没有看到揭幕动画 | 当前浏览器不支持视图过渡（如 Firefox），或动效开关已关闭，或系统开启了「减少动态效果」。功能正常，只是没有动画 |
| 界面卡顿、风扇转得快 | 在右上角关闭动效开关，背景气泡、场景轮播与卡片流光会全部停止 |
| 想把项目发给别人，压缩包太大 | 不要把整个文件夹打包（`node_modules` 约 169 MB）。执行 `npm run pack:share` 生成约 4.4 MB 的源码包，详见 README 的「分享与分发」一节 |

**彻底忘记密码、且没有绑定邮箱**：系统无法帮你找回。可以停止服务、先备份 `data`，在项目目录执行下面的命令清除账号（业务记录会保留，但归属信息也会一并清除），再启动时重新创建账号：

```sh
node -e "const {DatabaseSync}=require('node:sqlite');const db=new DatabaseSync('data/workbench.sqlite');db.exec('DELETE FROM account; DELETE FROM sessions;');db.close();"
```

> 更推荐的做法是平时就把邮箱绑定好，「忘记密码？」可以直接自助重置。

## 10. 开发与测试（可选）

- `npm run dev`：开发模式，前端 http://127.0.0.1:5178，改代码自动刷新。
- `npm test`：**58 组**单元测试；`npm run check`：单元测试 + 类型检查 + 构建；`npm run test:e2e`：5 组浏览器端到端测试（需 Google Chrome）。
- 测试全部使用临时数据库和本地模拟的模型服务，不会调用真实 AI，也不会改动 `data/`；邮件相关测试注入模拟发信函数，不会真的发邮件。测试截图输出到 `test-results/`，该目录已被忽略，可以随时删除。
- `npm run build:preview`：生成纯静态的演示版到 `dist-preview/`，数据存在访客浏览器，AI 不可用，只用于展示界面。
