## 0.4.3（2026-10-30）

本次重写鱼群背景的行为模型。原有实现是一条固定长链、队头恒定、四周有软边界，导致两个问题：队尾抖动明显；鱼群只能在画面内来回。数据库、接口与其它模块均不变。

### 变更

**1. 鱼群改为「一色一群」**

- 原来所有鱼串成一条固定链，队头永远是最先创建的那条。
- 现在按颜色分成 5 个独立鱼群、每群 5 条，各有自己的头鱼与牵引状态。
- 鼠标移动时只有「头鱼离鼠标最近」的那一群被牵引，其余群继续各游各的——不会五群一起冲向鼠标挤成一团。

**2. 头鱼动态判定**

- 群内头鱼取该群中离鼠标最近的那条，不再是固定的一条。
- 带 1.3 倍滞回：现头鱼没被明显甩开就不换，否则两条距离接近时会来回跳。

**3. 群内跟随改为「前驱树」**

- 每条鱼跟「同群中比自己更靠近目标、且离自己最近」的同伴，每 5 帧重算一次。
- 前驱距离超过 95px 就直接跟头鱼，否则会串成一条几百像素的长龙，尾巴永远追不上、鱼群也不会聚拢。

**4. 追上鼠标后自动解除牵引**

- 鼠标静止 1.2 秒后，若该群 60% 的鱼进入 150px 内，该群转为自由游动，头鱼重新开始漫游。

**5. 允许鱼群游出画面**

- 删掉了原来的软边界（`MARGIN` / `EDGE_TURN`），鱼群可以真的游出画框。
- 只剩不到 55% 的鱼在屏幕内时，把**画面外的鱼**从随机一侧边缘送回、朝屏幕内游。
- 屏幕内的鱼一条都不碰。早期写法是「出屏够多就把全部鱼重新摆位」，结果屏幕内正在游的鱼被一起搬走，整片鱼瞬间消失——这一版修掉了。

## 0.4.2（2026-10-29）

本次新增两个背景特效并做一次资源清理：**鱼群背景**（链式队列跟随鼠标）与**气泡可点破**（破裂后分裂子泡并溅出水雾）；同时移除了 3.1 MB 已无引用的旧背景图和两处失效样式。数据库结构、接口与既有功能均不变。

### 变更

**1. 鱼群背景特效**

- 新增 `src/components/FishBackground/`：`FishBackground.tsx`（挂载与生命周期）、`fishEffect.js`（绘制逻辑）、`fishEffect.d.ts`（类型声明）。登录页与工作台两处都挂载，叠在气泡之上、页面内容之下。
- 结构是**链式队列**而不是 boids：队列数 `min(5, floor(总数/6))`，25 条鱼时为 4 条队列（7+7+7+4）。队头追鼠标，其余鱼用弹簧跟随前一条身后 62px 并做速度对齐。
- 颜色按队列取（深色主题：蓝 / 青绿 / 紫 / 橙 / 粉），浅色主题另有一套；换主题时鱼不重建，只换调色板。
- 透明度沿队列递减（队头最实、队尾最虚）再叠加正弦呼吸，形成纵深。
- 鱼身是胖锦鲤造型：贝塞尔曲线画圆润鱼身，配分叉大尾、背鳍、胸鳍与眼睛；尾鳍按相位做轻微摆动。
- 与气泡共用同一套生命周期：跟随 `data-theme` 换色、`data-motion` 暂停（清空画布）、主题揭幕时分界线扫到哪里鱼就消失。

**2. 气泡可点破、分裂、溅出水雾**

- 背景画布是 `pointer-events: none`，所以点破事件挂在 `window` 上，并过滤掉 `button` / `a` / `input` / `textarea` / `select` 等交互元素，避免点按钮时误破泡。
- 命中判定用 `距离 < 半径 × HIT_SCALE + HIT_MARGIN`（2 / 12），多个泡泡重叠时取「侵入最深」的那个，而不是最近的那个。
- 破裂后按母泡半径分级分裂 2–8 个子泡泡，同时生成 12–21 颗水雾粒子和 1 个核心闪光（快速膨胀后消隐）。
- 子泡泡带水平速度，一边上升一边轻微左右漂移；泡泡总数上限 260，防止连点把数量撑爆。

**3. 两个背景组件合并**

`BubbleBackground.tsx`（43 行）与 `FishBackground.tsx`（44 行）除了 init 函数、canvas 类名和注释，其余「读 `data-theme` / `data-motion`、MutationObserver、主题揭幕、卸载销毁」的流程完全一样。抽成 `src/lib/useCanvasEffect.ts` 后，两个组件各剩 13 行：

```tsx
export function FishBackground() {
  const canvasRef = useCanvasEffect(initFishEffect);
  return <canvas ref={canvasRef} className="fish-bg" aria-hidden="true" />;
}
```

有效代码从 77 行降到 55 行，且这段样板只存在一份——以后再背景特效不用再抄一遍。钩子的第二个参数是模块级函数，引用稳定，不会因为重渲染反复初始化。

**4. 两处小整理**

- **文件大小格式化统一**：`Resources.tsx` 与 `ResourcePicker.tsx` 各写了一份 `fmtSize`，且 0 值时一个返回 `"0 B"`、一个返回空串。合并到 `src/lib/format.ts` 的 `formatFileSize()`：未传值返回空串（可直接参与模板拼接），0 返回 `"0 B"`。
- **收回多余的 `export`**：`FieldIssue`（api.ts）、`ConfirmOptions`（ui.tsx）、`MindmapLayout`（mindmap.ts）、`Editor`（editor.tsx）、`scenes`（SceneCarousel.tsx）都只在本文件内使用，去掉 `export` 让每个模块的对外边界准确。`createPreviewApi` 保留导出——`tests/audit.test.ts` 在用它。

**5. 资源与样式清理**

- 移除 `public/backgrounds/underwater-light-02.png`、`underwater-night-03.png`（各 1.5 MB）：0.4.1 把背景换成 `new-bg.jpg` 后它们已无任何引用，但 `vite build` 仍会把它们复制进 `dist/`。
- 移除项目根目录的 `new-bg.jpg`：与 `public/backgrounds/new-bg.jpg` 字节完全相同，属重复文件；原型页 `bubble-new.html` 的引用已改为 `./public/backgrounds/new-bg.jpg`。
- 移除两处失效样式 `.art-caption`（含 `responsive.css` 中的组合选择器）与 `.hero-art-label`：模板里已无使用。
- `public/` 从 4.4 MB 降到 1.3 MB。

## 0.4.1（2026-10-28）

本次是**视觉定制与兼容性**更新：登录页背景换成用户提供的深海科技图（`new-bg.jpg`），背景气泡重写为「深海气泡」款式；同时消除登录页左右分栏的黑缝与竖分界线、强化品牌标识的对比度，并把后端 Node 版本要求放宽到 22.5+。数据库结构与所有接口均不变。

### 变更

**1. 背景图换成用户提供的深海科技图**

- 原背景是两张按主题切换的 `underwater-*.png`，本次统一换成用户提供的 `new-bg.jpg`（科技感深海蓝，含光束、电路节点与气泡），放进 `public/backgrounds/`。
- 深浅两套主题仍各带一层半透明遮罩（浅色白 16%→34%、深色深蓝 62%→78%），把照片压到适合阅读的程度，正文对比度不受影响。

**2. 背景气泡改为「深海气泡」款式**

- 重写 `src/components/BubbleBackground/bubbleEffect.js`：从原来的「实心圆 + 点击爆破」改为**径向渐变气泡 + 描边 + 左上双高光点**，配色沿用深海蓝灰（`210,230,246` / `128,168,186` / `160,198,214`）。
- 尺寸分三层：大 16–40px × 14、中 6–16px × 30、小 1.5–5px × 80，与参考款 `bubble-new.html` 一致。
- 运动：自下而上漂浮 + 轻微正弦横向摆动，飘出顶部后回收到底部重新生成。
- **取消点击爆破**，改为纯装饰性漂浮；接口 `setTheme` / `setPaused` / `setSweep` / `destroy` 全部保留，主题切换、动效开关、主题揭幕照常工作，配色仍随主题联动。

**3. 登录页去除黑缝与竖分界线**

- 之前登录页左右两栏（`.login-shell`、`.login-art`）各有不透明的深色底，把底层的背景图盖住，形成黑色留白和一道竖线。
- 把这两处背景改为 `transparent`，让底层的 `new-bg.jpg` 铺满整页；同时去掉 `.login-art` 的 `border-right` 竖线。
- 左栏场景轮播图加**向右渐隐遮罩**（`mask-image`，70%→100% 淡出）并铺满（`inset: 0`），让场景图平滑融入右侧背景板，不再有硬边断层。

**4. 强化品牌标识对比度**

- 左上角「AI 办公助手」logo 曾因压在场景图偏亮的雾区上而对比度不足。在 `.login-art` 顶部加一层**暗色渐变遮罩**（`::before`，`rgba(3,9,16,0.88)` 向下 180px 渐隐），让白字落在深色底上。
- 图标改亮青色、文字加粗到 700 / 18px；去掉会发糊的大半径光晕（`drop-shadow` 8px、`text-shadow` 12px），改用 2px 紧贴投影，保证清晰锐利。
- 三个标签胶囊（智能写作 / 个人知识库 / 专注计时）的边框此前因 `--theme-border` 被重置而几乎看不见，改为写死的清晰边框色 + 半透明深色底。

**5. 兼容 Node 22.5+**

- `node:sqlite` 自 22.5.0 引入（22.x 需 `--experimental-sqlite`，23.4 起默认可用）。把 `server/index.ts` 的版本校验从 `< 24` 放宽到 `< 22`，并给 `dev` / `start` 脚本里的 tsx 加上 `--experimental-sqlite`，让 Node 22 也能启动后端（推荐仍用 24 LTS）。

## 0.4.0（2026-10-24）

本次新增第 13 个模块 **「资源库」**：可以上传 Word / Excel / PDF / 文本 / 图片，在线预览、下载并让 AI 快速分析；账号栏支持删除账号；登录页与工作台的场景轮播扩到四张并统一画幅。数据库结构不变，资源库复用 `entries` 表存元信息，文件本体落在 `data/files/`。

### 新增

**1. 资源库（第 13 个导航项）**

- 支持 `.docx`、`.xlsx`、`.pdf`、`.txt`、`.md`、`.csv` 与常见图片，单个文件上限 **50 MB**。

- **下载**：按原始文件名回传附件。
- **AI 分析**：把解析出的文本交给当前配置的模型，输出要点、结构与可执行建议；结果可存入知识库。
- 文件本体存磁盘（`data/files/`），数据库只存文件名、大小、类型等元信息。

**2. 删除账号**

- 四张统一为 **1548×816（1.90:1）**；新场景那张原为手机截图，已裁掉状态栏、电量、导航键与左右黑边；暗境由 792 KB 的 PNG 转成 182 KB 的 JPG。

### 实现说明

**为什么文件不塞进数据库**

把几十 MB 的二进制写进 SQLite，会让备份、迁移和 WAL 全部变慢，一次错误查询也可能把整库拖住。改成「文件落盘 + 元信息入库」后，备份 `data` 目录即可同时覆盖两者，删除账号时也能按目录一次性清理。

**为什么 Word / Excel 要转一道**

浏览器不能直接渲染 `.docx` / `.xlsx`。用 mammoth 转 HTML 能保留标题层级与列表，用 xlsx 解析后自己渲染表格可以控制列宽与滚动，比把文件丢进 iframe 或依赖外部预览服务更可控，也不联网。

**为什么用 linear 而且要把遮罩层提成合成层**

擦除要「每帧走一样多」，所以用 `linear` 而不是缓动曲线。但只改缓动还不够：`mask-position` 每帧都要重算遮罩，默认会和页面其它内容一起参与合成，实测掉到 43fps、还有一帧位移是均值的 2.6 倍（掉帧补偿）。给遮罩层加 `transform: translateZ(0)` + `contain: paint` 提升成独立合成层后，帧率回到 120fps，每帧位移稳定在 0.56%±0.02%。

**为什么擦除用 mask-position 而不是改 mask-image**

`linear-gradient` 之间浏览器不插值，直接把 `mask-image` 从「全显」换成「全隐」会一下跳到终态——图上瞬间没了，然后干等动画时长才换图，看起来就是卡帧。把渐变固定、放大到 200%，改成推进 `mask-position`，位置是可以插值的，进度才真正随时间走。

**为什么最终选擦除而不是滑动**

滑动是两张图并排走，接缝永远是硬边；想让接缝柔和就得让两图重叠，可重叠之后静止时又会从两侧露出邻图。擦除没有这个问题：两层完全叠在同一位置，上层被 `mask` 擦掉多少、下面那张就露出多少，边界干净利落、两层不会同时可见，而且图片本身不位移，视觉上更像「翻过去一页」而不是「把画布推开」。

**为什么四张图要统一画幅**

四张原来比例不一（3:2、2.2:1、1.9:1），铺满同一块区域时，构图的重心与留白都不一样，切换会显得画面「跳」。统一成 1548×816 后，四张在同一个 `cover` 容器里裁切，切换才连贯。

### 实现说明

**为什么改回左列，而不是留在全宽底栏**

两条全宽横栏会把整个页面的高度切成「顶栏 + 内容 + 底栏」，左侧导航被夹在中间只剩一条窄缝，账号块和导航抢同一列空间。改成左列内三段后：品牌和账号各自占一条固定高的横带，中间的导航拿到整列剩余高度，滚动也只发生在导航内部，上下两条带不会跟着跑。

**三条带怎么固定住**

`.app-sidebar` 是 `position: fixed; inset: 0 auto 0 0` 的纵向 flex 容器，`overflow: hidden`；`.sidebar-top` 与 `.sidebar-bottom` 都 `flex-shrink: 0`，中间 `nav` 用 `flex: 1; min-height: 0` 吃满剩余高度并自己滚动。`min-height: 0` 不能省，否则 flex 子项会被内容撑开、把底部栏顶出视口。

**手机端**

左列在手机上变成整宽，品牌与横向导航占顶部，账号栏改成固定在屏幕最底部的一条 58px 横栏（只保留头像、名称与退出登录），主区加 `padding-bottom` 让出位置。

### 实现说明

**为什么品牌和账号要「搬出去」而不是复制一份**

三段式布局的关键是三条边各司其职：顶栏负责「我是谁、我在哪」，底栏负责「我现在是什么状态、我要换人」，左列只负责「去哪」。原来品牌和账号都挤在 232px 宽的侧栏里，导航项只能分到一半高度，窗口一矮就出现滚动条。搬出去之后导航项自己占满整列，滚动条自然也就不需要了。

**滚动条是怎么藏掉的**

两层保险同时写：`scrollbar-width: none` 管 Firefox，`::-webkit-scrollbar { display: none }` 管 Chrome / Edge。只写其中一个，换浏览器就会露出来。同时给侧栏加了 `overflow-x: hidden`，因为导航项悬停时有 3px 的横向位移，不加的话会多出一条横向滚动条。

**顶栏 / 底栏为什么最后没用毛玻璃**

第一版给两条栏加了半透明背景 + `backdrop-filter`。实测截图里出现了「同一份内容被画两遍」的残影（头像和按钮下方多出半个偏移的轮廓），原因是固定定位的层再叠背景模糊时，合成层在截图时被重复绘制。导航栏是可读性优先的区域，改成纯色不透明更稳，视觉上也和参考图一致。

**主区怎么让开两条栏**

顶栏与底栏用 `position: fixed`，外壳 `.app-shell` 用 `padding-top / padding-bottom` 撑出等高空间，主区只保留 `margin-left`。三个尺寸写在外壳上（`--topbar-h` / `--bottombar-h` / `--sidebar-w`），手机端只改变量就能整体缩一档，不用逐条覆盖。

## 0.3.3（2026-10-17）

本次做三处视觉细节：**气泡跟着主题分界线消失、关动效时清空气泡、浅色主题的卡片换成毛玻璃**。只改前端，接口与数据结构未变。

### 新增

**1. 主题揭幕的分界线「吃掉」气泡**

- 分界线尚未扫到的区域（还在旧主题里）气泡保持原样，扫过的区域不再出现气泡。
- 揭幕结束后气泡从底部重新升起，恢复常态。
- 关闭动效、或浏览器不支持视图过渡时切换主题，气泡不做任何处理（瞬时换色）。

**2. 关闭动效时清空屏幕上的气泡**

- 原来只是停掉动画循环，屏幕上会留下一帧静止的气泡，看起来像动画卡住了。
- 现在「动效开 → 关」的瞬间，气泡与爆炸碎片一起清空，画布立刻擦干净。
- 重新打开动效时，气泡从底部重新生成，不会突然整片冒出来。

**3. 浅色主题的文本卡片毛玻璃**

- 浅色主题下，卡片从 96% 不透明白改为 66% 白 + 背景虚化（`blur(16px) saturate(1.4)`），底下的背景渐变与漂浮的气泡会虚化后透上来。
- 覆盖范围：`panel`（各模块主卡片）、`tool-card`（效率工具）、`demo-account`、`search-hit`、`knowledge-answer`、登录表单。
- 深色主题完全不受影响（仍是原来的 92% 深色卡面）。

### 实现说明

**气泡为什么能被分界线「吃掉」**

浏览器切主题时会先给「切换前」「切换后」各拍一张快照，分界线推的是**切换后**那张的遮罩。所以只要在拍照之前把画布清空，新快照里就没有气泡：分界线扫到哪里，哪里就从「有气泡的旧快照」换成「没有气泡的新快照」——看起来正是被分界线碰到就破掉。

时序是关键：清空必须发生在 `update()` **之前**，且同步。因此 `revealThemeChange` 把回调包了一层，先派发 `theme:reveal-begin` 事件再执行 `update()`：

```ts
const transition = start(() => {
  emitBegin();   // 气泡画布在此清空
  update();      // 浏览器在这之后立刻拍「切换后」的快照
});
transition.finished.then(emitEnd, emitEnd);
```

三个配套细节：

- 揭幕期间同时**停止生成**气泡（`sweeping` 标志），否则新气泡会从分界线后方又冒出来。
- 连续快速切换时会有多个过渡重叠，用 `revealDepth` 计数，最后一个结束才发 `reveal-end`，避免提前恢复。
- `transition.finished` 被跳过时会 reject，成功与失败走同一个 `emitEnd`，不会漏恢复。

**关闭动效为什么会出现「静止的泡泡」**

canvas 是独立图层，`setPaused` 原来只做 `cancelAnimationFrame`，最后一帧的像素留在画布上。现在暂停分支追加 `clearAll()`（清空列表 + `clearRect`），关闭动效看到的就是干净背景。

**毛玻璃的两个约束**

- 必须配合半透明卡面。原来的 `--frame-glass` 是 `rgba(255,255,255,0.96)`，几乎不透明，加了模糊也看不见底色。改成 0.66 后正文对比度仍约 7:1，远高于 WCAG AA 的 4.5:1。
- 用 `@supports` 做降级。不支持 `backdrop-filter` 的浏览器如果保持半透明，会变成一块**没有模糊的**磨砂玻璃，文字糊在背景上，所以这类浏览器退回 0.96 不透明。

- 一个工作空间可以注册多个账号，各账号的写作、会议、项目、文档、知识库、任务看板与操作日志**彼此完全隔离**，互不可见。
- 登录页改为「登录 / 注册新账号」两个 Tab；登录时列出已保存的账号，点一下即可填入账号名，不必手输。
- 退出登录改为「切换账号」：退出后重新拉取会话信息，直接进入另一个账号，无需重启服务。
- 所有 `/api` 业务接口都按当前登录账号过滤，数据隔离在服务端完成，不依赖前端传参，改不了也绕不过。
- 演示模式同步支持多账号：`localStorage` 按账号名分区存放。

**账号找回（邮箱验证码）**

- 登录页新增「忘记密码？」入口，两步完成：填入账号名或已绑定邮箱 → 收验证码 → 设新密码。
- 验证码 **6 位数字、5 分钟内有效、最多尝试 5 次**，数据库里只存 SHA-256 哈希，不存明文。
- 重置成功后自动注销该账号的所有登录会话，并清空验证记录。
- **防账号枚举**：账号不存在、没绑定邮箱、或未配置邮件服务时，一律静默返回成功提示，从响应上判断不出账号是否存在。

**邮箱绑定**

- 「个人资料」页可绑定邮箱，同样走验证码校验（先验证、后写入）。
- 一个邮箱只能绑定一个账号；已被其他账号占用时明确拒绝。

**邮件服务（SMTP）配置**

- 「设置」页新增邮件服务配置：服务器、端口、SSL / STARTTLS、发件账号、发件人名称、授权码。
- 授权码留空表示沿用原值，不必每次重填。

### 变更

- `AuthState` 的 `setupRequired` 布尔改为 `accounts` 数组，前端据此判断是首次注册还是多账号登录。
- `account` 表主键从固定的整数 `1` 改为**用户名文本**，支持一行一个账号。
- `sessions` 表新增 `accountId`，会话令牌与账号绑定；旧表结构在升级时直接重建（会话是临时数据，丢弃无影响）。
- `settings` 表新增 `accountId`，**API 地址与模型名称改为按账号保存**，各账号可以各自连接不同的模型服务。
- AI 的 API Key 仍为全局共享，只存在于服务进程内存中，与账号无关（重启后需重新填写）。

### 安全加固

- **SMTP 授权码不再明文入库**。填在设置页的授权码会用 **AES-256-GCM** 加密后再写入 `app_config` 表，解密密钥是 32 字节随机数，单独存放在数据库同目录的 `.mail-key` 文件中（权限尽量收紧到 0600）。数据库文件被单独复制走时，拿不到密钥就无法还原授权码。
- 启动时自动把旧版本遗留的**明文授权码就地升级为密文**，升级后仍能正常发信，无需重新填写。
- 新增**环境变量方式**配置 SMTP（`SMTP_HOST` / `SMTP_PORT` / `SMTP_SECURE` / `SMTP_USER` / `SMTP_PASS` / `SMTP_FROM_NAME`）：同时提供 `SMTP_HOST` 与 `SMTP_USER` 即视为启用。此方式下授权码**完全不写入数据库**，界面上对应字段变为只读并给出提示。环境变量优先级高于数据库。
- 接口始终**不返回授权码本身**，只返回 `configured` 布尔值，无论授权码来自环境变量还是数据库。
- `.gitignore` 增加 `.mail-key` 与 `*.mail-key`，避免密钥文件被误提交。

### 修复

- 修正索引创建时机：旧库在 `CREATE INDEX` 时还没有 `accountId` 列，会报 `no such column`。索引已从未能兼容旧库的建表语句中移出，改到迁移完成后再创建。
- **修复背景气泡特效在窗口缩放瞬间抛出 canvas 异常**：`Bubble.update()` 用 `1 - y / view.h` 计算半径，而 `view.h` 取自 `canvas.clientHeight || window.innerHeight`，在缩放/重排的一瞬间可能为 0，相除得到 Infinity 后算出负半径，`ctx.arc` 直接抛
  `The radius provided (...) is negative`，**整帧绘制中断、控制台持续报错**。
  现在：`view.h > 0` 才重算半径，并对结果做有限的正值兜底；`Bubble.draw()` / `Particle.draw()` 在半径非法时直接跳过绘制；碎片半径同样校验，`globalAlpha` 夹紧到 `[0,1]`。
  正常情况下的视觉表现完全不变，只是不再有异常。
- **修复知识库导入不校验文件编码**：原来用 `FileReader.readAsText()` 读取，非 UTF-8 文件会被静默解码成乱码（`U+FFFD`）并当作正常内容填进表单，可能被存进知识库。
  现在改用 `readAsArrayBuffer` + `TextDecoder("utf-8", { fatal: true })`，与「文档分析」的导入行为保持一致，遇到非 UTF-8 直接提示「不是有效的 UTF-8 文本，请转换编码后重试」。
- **修复 4 个浏览器端到端测试套件必然失败的问题**：`e2e-meetings` / `e2e-documents` / `e2e-projects` / `e2e-chat` 在断言里仍然使用单账号时代的固定账号 ID `"browser"`，而界面上注册的账号分别是 `meetings` / `documents` / `projects` / `chatuser`，因此 `store.history("browser")` 永远为空、断言必然失败（多账号改造后这几套用例一直没跑通）。现已改为使用各自实际创建的账号 ID，`npm run test:e2e` 五套用例全部通过。

## 升级到新版本

适用于所有新版本，**数据不会丢失**：

1. 停止旧版服务（在运行 `npm start` 的终端按 Ctrl+C）。
2. 备份旧目录里的 `data` 文件夹；旧目录先不要删除。
3. 把新版解压到一个新目录。
4. 把备份的 `data` 文件夹复制到新目录里，与 `package.json` 同级。
5. 在新目录执行 `npm ci`、`npm run build`、`npm start`，用原账号登录。
6. 启动时会自动完成数据库迁移，控制台不会有报错即可。
7. 在「设置」页重新填写 API Key（Key 只存在进程内存里，重启即清空）；API 地址、模型名称与 SMTP 配置都已保存在数据库中。
8. 确认记录、任务与操作日志都在以后再删除旧目录；有问题可以回到旧目录继续使用。

从 0.2.0 升级到 0.3.0 时，原账号会自动成为多账号中的第一个账号，原有数据全部归入该账号名下。

详细步骤见 [`安装与使用.md` 第 6 节](./安装与使用.md)。
