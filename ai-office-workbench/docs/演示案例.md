# 演示案例

以下是虚构的办公场景案例资料，人名、项目名、金额均为编写，用于功能演示和答辩操作，输入可直接复制。

这里不附「标准答案」：AI 每次生成的内容都会不同，请以当场结果为准，按每节的「检查要点」核对。模型没给出、原文也没有的信息（电话、落款日期等）如果被模型写了出来，直接在结果里改掉——这正是「先出草稿、人工确认后保存」的设计用意。

建议顺序（约 20 分钟）：设置 → 写作 → 会议 → 项目 → 文档 → 工程导图 → 知识库 → 问答 → 全局搜索 → 操作日志。

## 0. 准备

- 设置页填好 API 地址、模型名称和 API Key，点「保存并测试连接」，看到「连接成功」。
- 文档分析要用的文件已放在 `docs/案例资料/差旅费报销办法（示例）.txt`。

## 1. AI 写作

撰写（写作模式选「撰写」，标题填「季度复盘会通知」）：

```text
请写一则部门通知：本周五（9月26日）下午3点在302会议室召开第三季度工作复盘会，各小组组长需在周四下班前把本组季度总结（不超过5页）发给行政部陈静。语气正式简洁，200字以内。
```

检查要点：日期、时间、地点、截止时间、收件人与要求一致；原文没有的电话、落款日期应为占位或不写。然后演示：编辑结果 → 复制 → 导出 TXT → 保存 → 在左侧列表重新打开。

润色：

```text
这个方案我们大概看了一下，觉得整体上还是可以的，但是有些地方可能还需要再改一改，比如说预算那块写得不是很清楚，然后时间安排感觉有点太紧了，希望你们能再考虑一下，下周三之前给我们一个新的版本。
```

检查要点：意思不变，「预算不清楚」「时间太紧」「下周三前给新版本」三点都在。

摘要：

```text
公司计划于10月中旬将行政部和财务部从3楼搬到5楼东区。搬迁分两批进行：第一批10月15日（周三）搬行政部，第二批10月17日（周五）搬财务部。搬迁期间财务报销暂停两天，10月20日恢复。IT组负责网络和打印机迁移，需在10月14日前完成5楼布线检查。各部门请在10月10日前清点个人物品并贴好标签，贵重物品自行保管。搬迁费用预算为2.8万元，由行政部统一报销。
```

检查要点：日期、金额与原文一致，没有多出原文没有的安排。

## 2. 会议纪要

标题：`迎新活动筹备会`，会议日期：`2026-09-18`，会议原文：

```text
参会：王磊、陈静、刘洋、赵婷
王磊：今年迎新活动定在10月11日（周六），地点还是学校体育馆，预计120人参加。
陈静：预算上限8000元，比去年少了2000元，所以茶歇从两次减为一次。
刘洋：我负责联系音响和舞台灯光，周三前给出报价。
赵婷：宣传海报需要有人设计，目前还没定谁来做。
讨论后确定：活动流程控制在两个半小时以内；抽奖环节保留，奖品总额不超过1500元。
另外有人提出要不要请往届学长分享经验，这个下次会上再定。
```

操作：生成摘要草稿 → 在草稿里改一处 → 应用到会议纪要 → 保存。

检查要点：摘要包含时间地点人数、预算与茶歇、流程时长、抽奖上限；待办里有「刘洋周三前报价」；海报设计原文没定负责人，AI 不应替它指定某人；学长分享是「下次再定」，不是已决定事项。

## 3. 项目管理

标题：`部门制度资料整理`，项目说明：

```text
行政部现有的制度文件分散在个人电脑和群聊里，查找困难。计划用一个月时间把常用制度（报销、请假、采购、会议室预约、办公用品领用）整理成统一格式，存进办公助手的知识库，并给每份资料加上标签。整理完成后组织一次15分钟的使用说明会，让部门同事知道怎么检索。
```

操作：先点「保存」→ 生成任务草稿 → 取消勾选一条 → 改一条名称 → 确认加入所选 → 手动再加一个任务并改状态为「进行中」。

检查要点：加入的条数等于勾选数，不重复；任务里不应出现原文没有的截止日期或负责人。

## 4. 文档分析

操作：先到「资源库」上传 `docs/案例资料/差旅费报销办法（示例）.txt` → 回到「文档分析」新建文档，标题填「差旅费报销办法（示例）」→ 点「从资源库选择文件」选它 → 保存 → 生成分析草稿 → 修改一条要点 → 应用到分析笔记 → 保存。

检查要点：450 元、350 元、每天 80 元、10 个工作日、2026 年 10 月 1 日与原文一致；「原文预览与编辑」里的原文没有被改动。

## 7. 工程导图

沿用第 4 节的文档（标题「差旅费报销办法（示例）」，已导入案例原文并保存）。

操作：在该文档上点「生成工程导图」→ 等导图渲染出来 → 依次导出 SVG、PNG、Markdown 大纲。

检查要点：

- 根节点应该是文档主题（如「差旅费报销」），下面按费用类型或流程分支，**分支内容取自原文**，不应出现原文没有的项目。
- 节点文字不宜过长（单节点上限 120 字），应当是提炼后的短句而不是整段照搬。
- 页面上**任意两个节点框都不应重叠**，文字不被遮挡；画布贴合内容，四周没有大片空白。
- 导出的 SVG / PNG 与页面显示一致；Markdown 大纲是缩进列表，可直接粘进幕布、Obsidian 或 XMind。

如果结果是空树、只有根节点，或节点严重重叠，多半是模型没按 JSON 结构回答（会提示格式错误），重试一次或换一个更强的模型。

## 8. 知识库

先新建两条知识条目：

| 标题 | 关键词 / 标签 | 知识正文 |
| --- | --- | --- |
| 星桥计划出差说明 | 星桥计划,出差,住宿 | 见下方第一段 |
| 会议室预约规则 | 会议室,预约 | 见下方第二段 |

```text
星桥计划是公司与合作院校开展的联合调研项目。项目成员出差时，住宿统一由项目组预订协议酒店，个人无需垫付房费；如需自行预订，每晚标准为400元。项目期间的交通费用由项目经费单独列支，报销时在报销单备注栏填写“星桥计划”。项目联络人为行政部陈静。
```

```text
302和305会议室需提前一天在行政群内预约，单次最长占用3小时。临时会议可使用5楼开放讨论区，无需预约。会议结束后请关闭投影和空调。
```

也可以顺带演示「导入资料」：把上述任意一段存成一个 `.txt` 或 `.md` 文件，拖到「导入资料」区域，标题与正文会自动填进表单（**不会自动入库**，点保存才写入）。

然后在「关键词或问题」里依次提问并点「AI 整理答案」：

```text
星桥计划出差自己订酒店，每晚标准是多少？报销时要注意什么？
```

应答出 400 元和备注栏填写「星桥计划」，并标注来源编号 [1]。

```text
星桥计划的调研报告什么时候截止？
```

资料里没有写，应明确说明资料未提及，而不是给出一个日期。

```text
年会抽奖奖品有哪些？
```

没有任何资料命中，直接提示「知识库未找到相关资料」，不会调用 AI。

说明：检索是关键词匹配，中文按两字一组比对，问句里的常见词也可能命中不相关的资料，这时 AI 会说明资料不足。

## 9. AI 问答

第一问：

```text
我要给20名新入职的应届生做一场两小时的入职培训，请帮我列一个议程，包含时间分配。
```

第二问（依赖上一轮的议程）：

```text
时间临时缩短了，请把上面的议程改成一个半小时的版本，并说明删减或压缩了哪些部分。
```

检查要点：第二问的回答是在第一问议程基础上改的，而不是另写一份无关的内容。之后演示复制对话、导出 TXT、新对话（会先确认）。

## 10. 全局搜索

操作：侧边栏进「全局搜索」，依次输入 `陈静`、`预算`、`会议室`。

检查要点：

- 能同时命中不同模块的记录，每条结果标出所属模块。
- 结果里显示关键词前后的片段，一眼能看出为什么命中。
- 点一条结果会跳到对应模块并打开那条记录。
- 只搜得到当前账号自己的内容。

## 11. 操作日志与失败保留（可选）

- 删除一条写作记录 → 打开「操作日志」→ 找到这次删除 → 回溯 → 记录恢复。
- 在设置页点「清除密钥」→ 回到会议纪要点「生成摘要草稿」→ 提示需要先填写 API Key，原文和已有内容都还在。演示完在设置页重新填 Key。

## 12. 多账号与账号找回（附加演示，可选）

多账号与找回密码不属于 AI 功能，但演示价值高，建议各花一分钟。

**多账号切换**

1. 记下当前账号的一条记录标题（比如第 1 节保存的那篇写作）。
2. 「退出登录」→ 登录页点「注册新账号」→ 用另一个账号名注册并进入。
3. 到写作、项目、操作日志页看一眼：**内容都是空的**，看不到上一个账号的任何数据。
4. 再退出、用原账号登录：原来的记录都还在。

检查要点：两个账号之间数据完全不互通；登录页会列出已注册的账号，点一下即可填入账号名。

**邮箱验证码找回密码**（需先在「设置 → 邮件服务」配好 SMTP，并给账号绑定邮箱）

1. 退出登录 → 登录页点「忘记密码？」→ 填写账号名或已绑定的邮箱。
2. 邮箱收到 6 位验证码后填入，设置一个新密码。
3. 用新密码登录成功。

检查要点：验证码 5 分钟内有效、最多试 5 次；重置成功后原来的登录状态会失效，需要重新登录。若故意填一个不存在的账号，界面同样提示「验证码已发送」——这是防止账号枚举的设计，属于预期行为。
