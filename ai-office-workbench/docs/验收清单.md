# 验收清单

「我方验证」是开发方已经实际操作并通过的项目；「客户复验」请在你自己的电脑上逐项操作后再勾选。标为「待复验」的项目开发方尚未逐项手工走过，需要以你的复验结果为准。案例输入见 `docs/演示案例.md`。

验证环境（最近一次逐项走查：2026-10-15；2026-10-29 补测 0.4.x 新增功能，见 A6）：Windows 11，Node.js 24.14.0，Google Chrome，全新数据库。

这次走查没有依赖你本机的模型服务，而是用两个本地夹具替代，因此**除下面明确标注「待复验」的条目外，其余全部实际跑通过**：

- **假模型服务**（本地 OpenAI 兼容接口）：按系统提示词判断调用方是哪个模块，返回符合各模块结构的回复；并可切换成「返回非 JSON / 返回空内容 / 500 / 429 / 一直不响应」来验证失败路径。
- **假 SMTP 服务**（本地收信端）：真实接收 nodemailer 发出的邮件并还原验证码，所以「找回密码 / 绑定邮箱」的完整链路是真跑通的，不是在界面上点两下了事。
- 覆盖方式：接口层用脚本逐条断言；界面层用无头 Chrome 实际点击、读 DOM 与画布像素。

**这次走查顺带查出并修好了 3 个问题**（详见 `docs/更新说明.md` 的 0.3.0「修复」一节）：

1. 背景气泡特效在窗口缩放瞬间会抛 canvas 异常（负半径），导致整帧绘制中断、控制台持续报错 —— 已修复并加了边界兜底。
2. 知识库导入不校验编码，非 UTF-8 文件会被静默读成乱码 —— 已改为与「文档分析」一致，直接拒绝并提示。
3. 4 个浏览器端到端测试套件仍在用单账号时代的固定账号 ID 断言，多账号改造后必然失败 —— 已修正，`npm run test:e2e` 现在 5 套全部通过。

**你使用的模型服务与浏览器与此不同，B 部分的「内容质量」仍需你用自己的服务复验**（接口结构、草稿流程、错误处理已经验证过）。

## 已知限制

- 本机使用，不支持局域网 / 公网访问。支持多个账号，但都在同一台机器上，**不是多人协作**（没有共享数据、权限分级、并发编辑控制）。
- 文档分析只读 UTF-8 的 TXT / Markdown；资源库可解析 `.docx`（转 HTML）、`.xlsx` / `.csv`（转表格）与 `.zip`（自动解压），但 PDF 与图片仅支持下载，不解析正文。
- 知识库是关键词检索，不是向量语义检索；会议只处理文字原文，不含录音转写。
- 全局搜索是前端关键词匹配，不支持模糊匹配、同义词或拼音；数据量大时首次加载会拉取全部记录。
- 工程导图的层级与分支由模型决定，节点文字上限 120 字、每层最多 12 个分支；深度受输入 20,000 字上限约束，过深的树可能被模型自行简化。
- AI 问答不保存历史，刷新或离开后需要重新开始；AI 的 API Key 每次重启后重填（按设计不进磁盘）。
- SMTP 授权码的加密保护目标是「防止数据库文件被单独复制走」，密钥与数据库同机存放；如果整机被入侵，仍需按凭据泄露处理并去邮箱服务商重置授权码。
- 找回密码依赖 SMTP 可用；邮箱服务商通常对发信频率有限制，短时间大量发送可能被拒。
- AI 结果质量取决于所用模型，小模型可能编造细节，保存前需人工核对。
- 主题揭幕过渡依赖 View Transitions API，Chrome / Edge 111+ 与 Safari 18+ 支持；Firefox 及更旧的浏览器会直接瞬时切换，不会报错。
- 端到端测试需要本机已安装 Google Chrome；Playwright 自带的浏览器内核若未下载，测试会自动改用系统中的 Chrome 或 Edge。
- **已知的接口小瑕疵（不影响数据安全）**：`DELETE /api/entries/:id` 对「不存在」或「属于其他账号」的 id 也返回 `200 {ok:true}`（删除语句带 `accountId` 过滤，所以不会误删，实测其他账号的数据完好）；而 `GET` / `PUT` 对同样情况返回 `404`。响应语义前后不一致，属于可选改进项，目前不影响功能与隔离。
